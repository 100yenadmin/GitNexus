# GitNexus 1.6.10-electric.11

`1.6.10-electric.11` carries the post-M8b release-preparation contract for bounded embedding
preservation and staged recovery. It packages the already-supported paths; it does not add a
new preservation schema, lock, service, or public preservation command surface.

## Behavior contract

- **Healthy/source-stale copy:** run incremental analysis with a positive cap, for example
  `gitnexus analyze --embeddings <n>`. Unaffected embedding owners retain their complete
  logical row payload bytes while changed or new owners are regenerated within the cap.
- **Malformed/provenance-unproven copy:** run an explicit positive-cap staged clean rebuild:
  `gitnexus analyze --staged --embeddings <n> --drop-embeddings`. The disposable staged
  generation is validated before promotion; the canonical generation remains readable and
  unchanged until that boundary.
- The M8b disposable canary deterministically compared the complete unaffected embedding-row
  payload (identity, owner, chunk, line range, content hash, and vector). This proves logical
  row-payload preservation for that supported path; it does not claim raw LadybugDB container
  bytes are unchanged.
- Rows inherited from older metadata without durable provider or identity proof remain
  unproven and are not called verified preservation. The clean staged rebuild replaces that
  unclassified state rather than upgrading its claim.

## Safety and rollback boundary

- Staged recovery retains a canonical preimage and uses journaled promotion/rollback. The
  M8b receipt proves exact logical embedding-row and metadata preimage restoration after an
  injected promotion failure, with no staged, backup, or journal residue.
- `1.6.10-electric.10` remains available as the immediate non-writing rollback artifact.
- This source gate is local and disposable-copy evidence only. It does not prove the canonical
  65-index estate, fleet, production, customer, browser, or runtime readiness.

## Distribution boundary

- Electric releases are GitHub Release assets only. `.11` is not published to npm, a container
  registry, or any other package registry, and no floating tag is used.
- This release-prep change does not install, dispatch the release workflow, mutate a registry or
  live index, or perform a runtime/customer rollout.
